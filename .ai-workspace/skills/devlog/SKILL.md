# Antigravity 사용 일지 (antigravity-devlog)

## Overview

Antigravity와 함께 작업할 때마다 **내가 어떻게 Antigravity를 활용했는가**를
중심으로 개인 사용 일지를 자동 작성하는 스킬.

기술 문서가 아니라 **사용 경험 기록**이다. 나중에 돌아봤을 때 "그때 Antigravity에게
뭘 시켰고 어떤 결과가 나왔지?"를 빠르게 파악할 수 있도록 한다.

---

## 기록 위치

이 스킬은 반드시 프로젝트 워크스페이스의 루트 경로 아래에 `devlog` 폴더를 생성하고 저장해야 한다.
```
[Workspace Root]/devlog/
└── YYYY-MM-DD_<작업-제목-slug>.md
```

파일명 예시: `2026-05-24_antigravity-devlog-skill.md`

---

## 기록 트리거 (언제 devlog를 작성하는가)

다음 중 하나에 해당하면 devlog를 작성한다:

1. **자동 판단**: 의미 있는 결과물이 완성됐을 때
   - 새로운 파일 또는 기능이 생성/완성됐을 때
   - 버그나 문제가 해결됐을 때
   - 스킬, 컴포넌트, 모듈 단위 작업이 마무리됐을 때

2. **명시적 요청**: 사용자가 아래 표현을 쓸 때
   - "기록해", "devlog 써", "일지 남겨", "기록 남겨"

## Workflow

### 1. 작업 세션 분석

대화 맥락에서 다음을 파악한다:

- 어떤 프로젝트/파일에서 작업했는가
- 사용자의 최초 요청은 무엇이었는가
- 중간에 어떤 주고받음이 있었는가
- 최종적으로 어떤 결과물이 만들어졌는가
- 어떤 기술(언어, 프레임워크, 스킬, API)이 쓰였는가

### 2. 파일명 결정

- 형식: `YYYY-MM-DD_<slug>.md`
- 날짜: 현재 로컬 날짜 (KST 기준)
- slug: 작업 내용을 2~4단어로 요약, 소문자 + 하이픈
  - 예: `devlog-skill`, `login-page-ui`, `api-auth-fix`

### 3. 7가지 항목 채우기

프로젝트 로컬 폴더에 위치한 `.ai-workspace/skills/devlog/template.md`의 형식을 참조하여 아래 항목을 작성한다:

| 항목 | 작성 방법 |
|------|-----------|
| **어떤 상황이었나** | 프로젝트 배경, 작업 단계, 이 작업이 필요했던 이유 |
| **무엇을 원했나** | 이 작업 단위에서의 목표 (사용자 관점) |
| **어떤 요청을 했나** | 핵심 프롬프트나 대화 흐름 요약 (실제 요청 언어 반영) |
| **어떤 결과물이 나왔는가** | 생성된 파일 경로, 해결된 문제, 완성된 기능 목록 |
| **어떤 기술/도구를 사용했나** | 언어, 프레임워크, 스킬 이름, 외부 서비스 등 |
| **느낀 점 / 배운 점** | Antigravity가 인상적으로 처리한 것, 예상과 달랐던 점, 다음에 시도할 것 — **대화 흐름에서 추론 가능한 부분은 채우되, 주관적 감상이 불분명하면 빈칸으로 남겨 사용자가 직접 채울 수 있도록 한다** |

> [!NOTE]
> **느낀 점 / 배운 점**은 완전히 자동으로 채우지 않는다.
> 객관적으로 관찰된 사실(예: "계획-승인-실행 흐름이 명확했다")은 기록하되,
> 주관적 감상 영역은 `<!-- TODO: 직접 채워주세요 -->` 로 표시하여 사용자가 보완할 수 있게 한다.

### 4. 파일 저장

`write_to_file` 도구로 프로젝트 루트의 `devlog/YYYY-MM-DD_<slug>.md`에 저장한다.

`devlog/` 폴더가 없으면 자동 생성된다.

### 5. 완료 안내

저장 후 사용자에게 간략히 알린다:
```
📝 devlog 저장 완료: devlog/2026-05-24_example-task.md
```

## Common Mistakes

1. **기술 구현 중심으로 쓰지 말 것**: "어떻게 만들었나"가 아니라 "어떻게 요청했나"가 핵심이다.
2. **너무 길게 쓰지 말 것**: 각 항목은 3~5문장이면 충분하다. 나중에 훑어볼 수 있는 밀도가 중요하다.
3. **느낀 점을 억지로 채우지 말 것**: 주관적 감상은 빈칸으로 남겨 사용자가 직접 채우게 한다.
